# 交易日记周期收益曲线设计

## 背景

交易日记已有月、周、列表、季、年五种视图。月和周展示交易日历，季和年展示周期复盘入口；现有账户指标只能看到当日盈亏和周期最大回撤，无法直接观察当前周期内的累计收益变化。

本次在月、周、季、年四个周期视图下方增加累计收益曲线。列表视图保持不变。

## 已确认需求

- 图表类型为累计收益曲线，不展示每日盈亏柱状图或组合图。
- 月、周、季、年使用各自当前周期边界；切换周期或前后翻页后自动刷新。
- 周期首个有效净值点显示为 `0%`。
- 收益率基于现有资金流调整净值，剔除入金和出金影响。
- 月、周视图中，图表位于日历和当日明细下方。
- 季、年视图中，图表位于账户指标下方。
- 周期复盘入口或已生成报告位于收益图之后。
- 最终累计收益为正时使用 A 股盈利红色，为负时使用亏损绿色；零值使用中性色。

## 非目标

- 不在列表视图增加图表。
- 不增加基准指数、每日盈亏柱、回撤曲线、缩放或区间选择器。
- 不改变账本、净值和最大回撤的既有计算口径。
- 不要求先生成周期复盘报告。
- 不新增后端端点或前端图表依赖。

## 方案

扩展现有 `GET /api/trading/period-summary`，让同一次请求同时返回周期最大回撤和累计收益点。前端月、周、季、年统一请求该接口，并使用独立的轻量收益曲线组件展示结果。

未采用以下方案：

- 从月历的每日盈亏推导：无法稳定还原剔除资金流后的累计收益率，并导致月视图与其他周期使用不同口径。
- 复用周期复盘报告：会让基础视图依赖报告生成状态，不符合打开视图即可查看收益的要求。

## API 契约

`GET /api/trading/period-summary?start=YYYY-MM-DD&end=YYYY-MM-DD` 保留现有字段，并新增 `return_curve`：

```json
{
  "start": "2026-08-01",
  "end": "2026-08-31",
  "max_drawdown": "0.0375",
  "return_curve": [
    {
      "date": "2026-08-03",
      "cumulative_return_rate": {
        "value": "0",
        "unavailable_reason": null
      }
    },
    {
      "date": "2026-08-04",
      "cumulative_return_rate": {
        "value": "0.0124",
        "unavailable_reason": null
      }
    }
  ]
}
```

前端 `TradingPeriodSummary` 对应新增 `returnCurve`。每个点包含日期和一个现有
`NullableDecimalMetric` 结构，适配器继续执行精确字段校验、日期校验和十进制字符串校验。

## 计算规则

后端继续通过 `AccountValuationService.nav_points` 获取成立以来的资金流调整净值点，然后截取请求周期。

1. 找到周期内首个 `nav` 大于 `0` 的点，记为基准净值 `base_nav`。
2. 基准点及之后每个可用点计算 `point.nav / base_nav - 1`。
3. 基准点累计收益率固定为 `0`。
4. 基准点之前 `nav` 为 `0` 的点按 `zero_equity_baseline` 返回不可用；基准点之后
   `nav` 为 `0` 时正常计算为 `-100%`。
5. `nav` 不可用的点保留日期和不可用原因，收益率值为 `null`；前端在该处断线。
6. 周期内没有正净值点时，后端仍返回全部不可用点；前端显示空状态，不绘制零收益线。
7. 金额和比率继续以十进制字符串跨越 API 边界，不用浮点数承担账本计算。

最大回撤继续使用现有 `window_max_drawdown`，不因新增曲线改变。

## 前端数据流

`TradeJournalPage` 对月、周、季、年统一使用 `reviewPeriodBounds` 计算周期边界，并调用 `getPeriodSummary`。列表视图不发起该请求。

以下变化会清空旧摘要并重新请求：

- 切换月、周、季、年视图。
- 点击前一个或后一个周期。
- 选择影响周视图边界的交易日期。
- 新增或删除成交、资金流水后账本修订变化。

请求返回前不展示上一个周期的曲线。组件卸载或周期变化后忽略迟到响应，沿用当前 `active` 守卫模式。请求失败继续进入交易日记现有错误提示，不额外增加通知系统。

## 图表组件

新增独立的交易日记收益曲线组件，复用项目现有 ECharts `LineChart`、
`GridComponent`、`TooltipComponent` 和 `CanvasRenderer`。

图表包含：

- 标题：本月、本周、本季或本年累计收益。
- 右上角：周期最后一个有效累计收益率。
- 横轴：周期内全部净值点日期，包括收益率不可用的日期。
- 纵轴：累计收益率百分比。
- 参考线：`0%` 虚线。
- 悬浮提示：日期和累计收益率。
- 颜色：末值大于零用 `--up`，小于零用 `--down`，等于零用中性色。

图表使用全宽卡片，桌面高度约 260px；窄屏保持全宽并降低横轴标签密度。容器使用 `ResizeObserver` 响应布局变化，并在卸载时释放图表实例。可访问名称包含周期名称和“累计收益曲线”。

## 页面布局与状态

- 月、周：交易日历与当日明细之后展示收益图，随后展示周期复盘入口或报告。
- 季、年：账户指标之后展示收益图，随后展示周期复盘入口或报告。
- 加载中：收益图卡片显示读取提示，不保留旧周期曲线。
- 无有效点：显示“该周期暂无可用收益数据”。
- 单个有效点：显示 `0%` 末值和单点，不伪造趋势。
- 部分点不可用：曲线在对应日期断开，悬浮提示显示不可用原因。

## 测试与验证

后端定向测试覆盖：

- 周期首个有效点归零。
- 后续点按资金流调整净值归一化。
- 入金和出金不直接制造收益。
- 不可用净值点保留原因。
- 无有效净值时保留全部不可用点及其原因。
- 非法周期边界继续返回既有错误。

前端定向测试覆盖：

- `period-summary` 新字段适配和非法响应拒绝。
- 月、周、季、年切换时请求正确边界并传入对应曲线。
- 列表视图不请求、不展示收益图。
- 加载、空数据、正收益、负收益和单点状态。
- ECharts 配置包含百分比轴、`0%` 基准线、日期提示和 A 股红涨绿跌颜色。
